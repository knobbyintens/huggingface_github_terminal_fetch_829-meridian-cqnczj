# Downstream Reuse Licensing Policy

Version 2.3 - applies to all artifacts released by the Meridian program.

## 1. Source set

For every artifact, determine the complete set of sources whose content is
incorporated:

- every corpus or collection whose documents or records are included, and
- every generative model used to synthesize content that is included.

Identify sources from the artifact's own documentation. Do not rely on the
artifact's short Hub tags, on the apparent provenance weight of a source, or on
the familiarity of a license name.

## 2. Read the terms

Locate the authoritative license text for each source and read its actual terms
on derivative works, redistribution and secondary use. A Hub tag such as
`license: other` is not a license; the full text governs.

## 3. Selection rule

a. If an artifact incorporates content generated by a model, compare the
   candidate licenses' actual terms and adopt the source license that is most
   permissive for derivative and secondary use. Attribution-only open data
   licenses, which allow sharing, adaptation and commercial reuse without
   use-based restrictions, are more permissive than a custom model license that
   imposes use-based restrictions and requires derivatives to carry them.

b. If an artifact consists solely of corpus data, adopt that corpus's license.

c. If a model license states that the model owner claims no rights in, or
   assigns ownership of, the generated output to the user, the generated content
   is not itself subject to that model license; the license of the incorporated
   corpus continues to govern.

## 4. Fallback

If a license cannot be established for a source from the available evidence,
record the literal value `unknown` for the artifact and escalate. Do not infer,
guess or substitute a license.

## 5. Identifiers

Record identifiers in lowercase SPDX style (for example `cc-by-sa-4.0`,
`bsd-2-clause`, `mpl-2.0`). For the fallback case use `unknown`.
